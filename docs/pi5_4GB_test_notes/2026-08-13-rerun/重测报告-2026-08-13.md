## 4. SLIM-ARC 专属项验证结论

| 项 | 预期 | 实测 | 结论 |
|---|---|---|---|
| `SLIM_ARC_DISABLE=1` | 走 baseline 路径不崩溃 | T2 正常完成，无 SLIM-ARC 日志行 | ✅ |
| expert prefetch 指标 | Dense 模型不触发 | 各次退出均输出 `samples=0 issued=0.0MB hit=0.0MB waste=0.0MB` | ✅ 未误触发 |
| `SLIM_ARC_KV_EVICT=1` | hook ENABLED，短上下文不触发 | `SLIM-ARC KV eviction: ENABLED (sink=4, window=1024)`，无 evicted，EXIT 0 | ✅ |
| `SLIM_ARC_NO_MADV_RANDOM=1` | <6GB 本就不触发 MADV_RANDOM | 无 MADV 输出，EXIT 0，性能无差异 | ✅ |
| KV q4_0 / FA / ctx1024 | 均正常运行 | 全部 EXIT 0，无 OOM | ✅ |

**核心结论**：Qwen3-4B（2.32 GiB < 6GB 阈值）在 Pi5 4GB 上 `model_fits` 为真，
SLIM-ARC 优化路径不激活，全程运行 baseline 路径，所有开关行为符合 08-05 的预期。

## 5. 诚实声明（数据解读边界）

1. **吞吐提升来自 upstream 版本升级**，不是 SLIM-ARC：二进制由 b1（1c3c967）→ b106（70dfba5），
   期间 llama.cpp 的 ARM 内核（Q4_K 点积、FA 默认行为、调度器）有多轮优化。
   SLIM-ARC 对 Qwen3-4B 未激活（§4），两者对比不能记为优化收益。
2. **"冷启动"名不副实**：无 sudo 无法 `echo 3 > /proc/sys/vm/drop_caches`，
   raw-51-basic-cold 运行时模型已在 page cache（buff/cache 2.6 GiB）。
   冷/热两次结果完全一致（12.2/4.6）印证了这一点。真实 microSD 冷启动数据见 08-04 vanilla 基线
   （`reports/raw_analysis/pi5-4gb-edge-test-summary.md`，pp64 10.16 / tg32 3.48 为 08-05 热缓存值）。
3. **swap 已有 412 MiB 占用**是测试前系统既有状态（可能来自前一次被中断的长跑），
   测试前后数值不变，对本次推理指标无实质影响，但已如实记录。
4. 冒烟时曾出现一次事故：`--no-conversation` 参数下 llama-cli 在 `-n 8` 后进入交互空循环，
   产生 1.6GB 输出文件（已删除并改用 `--single-turn < /dev/null` 重跑）。本报告数据均出自重跑后的有效记录。
