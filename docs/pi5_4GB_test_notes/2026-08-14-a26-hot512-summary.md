# A26 resident-only 热专家缓存：Pi5 慢盘确认

## 结论

A26 在 A24“关闭专家推测预取”的基础上，启用 `SLIM_ARC_EXPERT_HOT_MB=512`。它只对已经
通过真实计算 demand-fault 进入内存、并在连续 token 中重复命中的专家页执行 `mlock`；不会为了
填充 cache 主动读取非驻留页。

两次 Raspberry Pi 5 cold/no-swap 运行分别为 522s 和 523s，范围只有 1 秒。相对 A24：

- Prefill: `0.201104 -> 0.200578 t/s`，`-0.26%`，基本持平。
- Decode: `0.055614 -> 0.060726 t/s`，`+9.19%`。
- Wall: `547 -> 522.5s`，`-4.48%`。
- Expert speculative I/O: 两次均为 `0 bytes`。

| Run | Prefill (t/s) | Decode (t/s) | Wall (s) | Locked bytes | Hot hits | Evictions | Lock failures |
|---|---:|---:|---:|---:|---:|---:|---:|
| r1 | 0.200541 | 0.0607827 | 522 | 304,414,720 | 1,691 | 811 | 0 |
| r2 | 0.200615 | 0.0606701 | 523 | 307,183,616 | 1,691 | 811 | 0 |

## 机制解释

Pi5 的 48GB 模型位于 USB NTFS/FUSE 机械盘，4GB 内存无法保留一轮 decode 触及的全部专家页。
A24 已证明错误 `WILLNEED` 不值得做；A26 进一步把约 306MB 已经验证会复用的专家页保护在内存中，
避免下一 token 再次经过 FUSE 同步缺页。每轮都得到 1,691 次 hot hit、0 次预算拒绝、0 次 mlock
失败，且 wall 收益重复稳定。

这对应调研路线中的 per-layer expert residency/cache，但采用 resident-only admission：cache miss
仍由系统 demand paging 处理，不让 cache admission 本身和真实读取竞争慢盘。

## 决策

A26 提升为 Pi5 slow-storage 候选配置：

```bash
SLIM_ARC_NO_EXPERT_PREFETCH=1 SLIM_ARC_EXPERT_HOT_MB=512
```

目前仍保留显式环境开关，不按 `SLIM_ARC_SLOW_STORAGE=1` 自动启用：1GiB 内存档历史上固定
hot cache 会挤压通用页缓存。下一步继续测试降低普通权重预取预算，以及约 92MB always-on shared
expert 常驻能否与 A26 叠加。

## 无效预算筛选

A27 曾在同一 Pi 二进制上额外设置 `SLIM_ARC_TOTAL_BUDGET_MB=16`，结果 wall 为 525s，但
`weight_issued_bytes` 仍与 A26 完全相同，都是 4,080,156,672。该 A23 二进制来自双方 merge 前的
开发线，不包含队友随后加入的总预算解析，因此这个环境变量实际是 no-op。A27 不用于预算结论；
需要先把合并后的源码增量构建到 Pi，再重新测试权重预算。
