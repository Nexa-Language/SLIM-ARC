# 根因分析: escapeHtml 函数无效导致 HTML 注入

## 日期: 2026-08-10

## 根因描述
index.html:513-515 的 escapeHtml 函数存在 bug：HTML 实体替换值为空操作
（`&`→`&`, `<`→`<`, `>`→`>`），实际未做任何转义。
当模型输出包含 `<` 或 `>` 字符时，innerHTML 会将其解析为 HTML 标签，
可能导致后续内容被"吞掉"，表现为"输出一段就停"。

## 证据链

### 证据1: hexdump 确认替换值为空操作
```
# 原始字节:
return s.replace(/&/g,'&').replace(/</g,'<').replace(/>/g,'>').replace(/\n/g,'<br>');
```
hexdump 确认:
- `/&/g,'&'` → 匹配 `&` 替换为 `&` (0x26 → 0x26, 无变化)
- `/</g,'<'` → 匹配 `<` 替换为 `<` (0x3c → 0x3c, 无变化)
- `/>/g,'>'` → 匹配 `>` 替换为 `>` (0x3e → 0x3e, 无变化)

正确的实现应为:
- `&` → `&`
- `<` → `<`
- `>` → `>`

### 证据2: innerHTML 使用场景
```javascript
// line 497 (流式渲染)
bubble.innerHTML = escapeHtml(text) + '<span class="cursor"></span>';
// line 504 (最终渲染)
bubble.innerHTML = escapeHtml(text) || '<span style="color:#8892b0">(无输出)</span>';
```
使用 innerHTML 赋值，未转义的 `<` `>` 会被浏览器解析为 HTML 标签。

### 证据3: 潜在影响场景
- 模型输出包含 `<think>` 标签（Qwen3 thinking 模式泄露时）
- 模型输出包含代码片段（如 `<div>`）
- 模型输出包含数学符号（如 `a < b`）
- 在这些场景下，`<` 后的内容可能被浏览器当作 HTML 标签属性，
  导致后续文本不可见，表现为"输出一段就停"

## 影响评估
- 此 bug 在当前场景下不是主因（系统提示限制是主因）
- 但在模型输出包含 `<` 或 `>` 时会触发，属于潜在渲染 bug
- 修复风险极低（仅修正替换值，不改变逻辑）

## 结论
escapeHtml 函数无效是"输出一段就停"的**潜在/次要根因**。
在特定输出内容下（含 `<` `>` 字符）会导致内容被 HTML 解析器吞掉。
