3. 左侧聊天窗口滚动失效的真实根因（带行号证据）
------------------------------------------------------------------------------
【布局链】
  body(100vh, overflow:hidden, 行 25-26)
    └ .main(grid, height:calc(100vh-56px), 行 56-62)  ← grid-template-rows 默认 auto
        ├ .chat(grid item, flex column, 行 64-67)     ← overflow:visible、无 min-height
        │    ├ .chat-header（行 68-72, 固定高）
        │    ├ .chat-messages#messages(flex:1, overflow-y:auto, min-height:0, 行 73-76)
        │    └ .chat-input（行 109-113, 固定高）
        └ .monitor(grid item, overflow-y:auto, 行 136-140)

【根因】
  a) .main 的 grid-template-rows 未定义 => 默认 auto（由内容决定行高）。
     行高一旦被内容撑大，grid 容器(高度固定 calc(100vh-56px))不会把行压回容器高度，
     内容溢出 .main，再被 body 的 overflow:hidden（行 26）直接裁剪。
  b) .chat 是 grid item 且 overflow:visible、未设 min-height => 自动最小尺寸为
     min-content（CSS Grid §6.6: overflow:visible 的 item 自动最小尺寸=内容最小尺寸）。
     当聊天消息累积变长时，.chat 的 min-content 高度被 .chat-messages 内容撑高，
     导致 .chat 不会被压缩到 grid 行高（容器高度），整栏随之增高。
  c) 后果: 一旦消息高度超过可视区，.chat 高度 > .main 高度，.chat-messages 的
     flex:1 分配到的高度 = .chat 高度 - header - input（足够容纳全部消息），
     于是 .chat-messages 内部从不溢出 => overflow-y:auto 永不触发滚动条；
     超出部分被 body 裁剪，左栏无法上下滚动、输入框可能被挤出。
  d) 上次修复只给 flex 子项 .chat-messages 加了 min-height:0（行 75），这只允许
     ".chat-messages 自身"在 flex 中收缩，并未处理外层 grid item .chat 的
     min-height:auto 与 grid 行高 auto 问题 => 因此左栏仍不可滚。
     （这正是"改一处未验证到点上"的缺口：问题层级在 .chat/.main，不在 .chat-messages。）

------------------------------------------------------------------------------
4. 修复方案（最小、逐处）
------------------------------------------------------------------------------
  FIX-A: .chat 增加 min-height:0  → 覆盖 grid item 默认自动最小尺寸，允许 .chat
         收缩到 grid 行高，使内部 .chat-messages 的 overflow-y:auto 可激活。
  FIX-B: .main 增加
         grid-template-rows: minmax(0, 1fr);  → 明确行高=容器高度(且允许内容溢出不撑行)，
         消除 auto 行被 .chat 内容撑大的路径。
  保留: .chat-messages 的 min-height:0（上次正确部分）与 auto-scroll 容差逻辑（行 510-513）。
  严禁: 不触碰 MoE 可视化（updateExperts/initExperts/pollMonitor 专家段、Math.random 等）。
