## 1. 第一阶段：80B 实验（2026-08-06）

### 1.1 Phase 0：环境与带宽预检
- SSD 挂载确认：`/dev/nvme0n1p7`（ext4，222GiB 可用）
- **SSD 顺序读 2.1 GB/s（direct）**，写 242 MB/s（远优于昨日 microSD 68.6MB/s）
- SLIM-ARC 符号确认存在于 `libllama.so`（prefetch_scheduler / kv_eviction_manager / unified_io_scheduler）
- 产物：`原生数据/环境与模型/ssd-bw-test.txt`

### 1.2 Phase 1：模型下载与校验
- Qwen3-Next-80B-A3B Q4_K_M，45.09GiB（48,410,988,384 字节）
- 下载：hf-mirror.com，初始 wget 0.6MB/s 过慢，改自研 Python 多线程分块下载（8 并发），提速约 20 倍（6.5-14MB/s），6862s 完成 0 失败块
- SHA256：`d103b2733ec1012a52d01edda66b7e5c24ae50508c9f99f5297ea459ef3c061a`
- llama-cli 识别确认（qwen3next 80B.A3B Q4_K - Medium，48 层，807 张量）
- 产物：`原生数据/环境与模型/model-verify-80b.txt`

### 1.3 Phase 2：冒烟测试（三组开关对比）
| 配置 | Prompt (t/s) | Gen (t/s) | RSS 峰值 |
|:---|:---:|:---:|:---:|
| 默认（SLIM-ARC 全开） | 0.5 | 0.5 | 6.29 GiB |
| SLIM_ARC_DISABLE=1 | 1.7 | 1.9 | 6.26 GiB |
| SLIM_ARC_NO_MADV_RANDOM=1 | 1.4 | 1.8 | 6.50 GiB |

**关键证据**：VmSize 46.6GiB（完整映射）但 RSS 仅 6.29GiB → mmap 按需分页生效。
产物：`原生数据/冒烟与TTFT/`

### 1.4 Phase 3：性能矩阵（B1-B7）
| 配置 | pp (t/s) | tg (t/s) |
|:---|:---:|:---:|
| B1 基线全开 | 0.39 | 0.23 |
| B2 DISABLE | 2.02 | 0.89 |
| B3 NO_MADV | 1.41 | 0.65 |
| B4 NO_PREFETCH | 0.37 | 0.24 |
| B5 长上下文 | 0.55 | 0.30 |
| B6 t8 | 0.89 | 0.48 |
| B7 t2 | 0.23 | 0.17 |

- TTFT ≈ 121.1s（含加载 ~60s）；RSS 峰值 6.38GiB
产物：`原生数据/bench矩阵/`、`原生数据/冒烟与TTFT/raw-80b-ttft.txt`

### 1.5 Phase 4：SLIM-ARC 专项验证（LD_PRELOAD 拦截 madvise）
- 系统无 strace/无 root，自研 `madvise-trace` 拦截库（编译后已删除，源码为 debug 中间产物）
- **默认配置**：`posix_madvise(RANDOM, 45.1GiB)` ×1（MADV_RANDOM 触发）+ `WILLNEED` ×1 + `DONTNEED` ×3
- **NO_MADV_RANDOM 配置**：RANDOM 调用消失、WILLNEED 保留 → 开关有效
- **结论：SLIM-ARC MADV_RANDOM 按需分页在端侧 >6GB 模型首次确认触发**
产物：`原生数据/madvise验证/`

## 2. 第二阶段：长上下文测试（2026-08-07）

### 2.1 阶段 A：-c 1024 基线复核（LC1-LC4）
- 用时 ~18min；趋势与 B1-B4 一致（LC1 < LC3 ≈ LC2）
- 确认环境无漂移，准入通过

### 2.2 阶段 B：-c 4096 主对比矩阵（LC5-LC13）
- 用时 ~42min；6 bench + 3 cli 全部 EXIT=0
- 全开 tg 0.53 vs 禁用 2.13 → SLIM-ARC 仍负优化

### 2.3 阶段 C：-c 8192 大上下文（LC14-LC20）
- 用时 ~55min；含 -n 256 长生成交叉点验证
- **LC17（全开 0.57）vs LC18（禁预取 0.55）→ 无 decode 交叉点**
- LC19 RSS 6.50GiB 无 OOM

### 2.4 阶段 C+：-c 16384 超大上下文（LC21-LC23）
- 用时 ~21min；无 OOM（混合 SSM 架构 KV 增量小）
- LC23 KV q4_0 量化轻微降性能（tg 0.47 vs 0.53）但省内存

### 2.5 阶段 D：KV eviction 专项（LC24-LC26）
- 用时 ~58min；长 prompt ~1360 tokens 触发驱逐
- **LC24（W=256）**：`KV eviction: ENABLED` + `evicted [4,1104)` 首轮批量，RSS 6.34GiB
- **LC25（W=1024）**：首轮 `evicted [4,336)`，RSS 6.44GiB
- **LC26（无驱逐）**：RSS 6.49GiB
- **结论：KV eviction 确认触发且窄窗口降 RSS，为唯一正收益机制**

## 4. 遇到的问题与处理

| 问题 | 处理 |
|:---|:---|
| 模型下载慢（wget 0.6MB/s） | 改用自研 Python 多线程分块下载（8 并发），提速 ~20× |
| `/usr/bin/time` 不存在 | 改用 bash 内置计时 + `/proc/<pid>/status` VmHWM 监控 RSS |
| llama-bench 不支持 `-c` 参数 | 用 `-p` 控制上下文规模（已记录为参数偏差） |
| RSS 监控绑定 bash 包装进程失效 | 改用 `pgrep -x llama-cli` 动态定位真实进程 |
| 无 strace/无 root 验证 madvise | 自研 LD_PRELOAD 拦截库（`madvise-trace`），验证后删除代码 |
