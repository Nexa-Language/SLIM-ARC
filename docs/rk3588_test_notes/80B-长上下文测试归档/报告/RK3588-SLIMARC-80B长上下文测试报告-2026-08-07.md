## 5. 关键发现与分析

### 5.1 长上下文下 SLIM-ARC 仍为负优化

| 指标 | 短上下文 (c256) | 中 (c4096) | 大 (c8192) | 超大 (c16384) |
|:---|:---:|:---:|:---:|:---:|
| 全开 tg | 0.23 | 0.53 | 0.53 | 0.53 |
| 禁用 tg | 0.89 | 2.13 | 2.15 | 1.64 |
| 差距倍率 | 3.9× | 4.0× | 4.1× | 3.1× |

**结论**：即使将上下文从 256 增至 16384、生成长度从 16 增至 256，SLIM-ARC 的 MADV_RANDOM 惩罚始终占主导，**未出现长生成 decode 稳态下按需分页的收益**。这与性能分析文档的"动态切换未实现"结论一致——静态全量 MADV_RANDOM 同时破坏了 prefill 顺序预读且未兑现 decode 随机访问收益。

### 5.2 KV eviction 是长上下文测试中唯一正收益机制

- **确认触发**：`SLIM-ARC KV eviction: ENABLED (sink=4, window=N)` + 批量驱逐（LC24 首轮 `evicted [4,1104)`，LC25 首轮 `evicted [4,336)`）
- **降低 RSS**：窄窗口 6.34 < 宽窗口 6.44 < 无驱逐 6.49 GiB（驱逐生效，0.15 GiB 差异）
- **驱逐后输出连贯**：驱逐后继续生成 `seems/you/'ve` 等，文本未中断
- **窗口选择权衡**：窄窗口（256）首轮大块驱逐降 RSS 更明显，但驱逐日志少（105 条）说明进入稳态后驱逐频率低；宽窗口（1024）驱逐日志多（255 条）

### 5.3 内存边界：-c 16384 仍无 OOM

即使上下文翻倍至 16384，RSS 峰值仍稳定在 ~6.5GiB。原因是 Qwen3-Next-80B 是混合注意力+SSM 架构，SSM 层状态固定大小不随上下文增长，实际 KV cache 增量低于纯注意力架构的估算。8GB 内存有约 1.5GB 余量。

### 5.4 KV cache 量化（q4_0）轻微降性能

LC23（KV q4_0）pp 2.04 / tg 0.47 vs LC21（f16）pp 2.36 / tg 0.53 —— KV 量化降低约 13% 性能但节省内存，可作为内存紧张时的降级方案。

## 6. 结论与限制

### 6.1 结论

1. **长上下文下 SLIM-ARC 整体仍负优化**：MADV_RANDOM 静态全量设置是持续的性能瓶颈，长生成/大上下文未改变这一局面。
2. **KV eviction 机制验证有效**：这是 SLIM-ARC 在大上下文内存压力场景下**唯一确认的正收益机制**——能降低 RSS 峰值且保持输出连贯。
3. **预取机制无收益**：长生成下预取开/关无差异，SSD 快 + 权重页命中模式的现状下预取是纯开销。
4. **内存边界远超预期**：-c 16384 仍无 OOM（混合 SSM 架构 KV 增量小），8GB 内存在此场景下并非硬约束。

### 6.2 对 SLIM-ARC 的定位建议

- **MADV_RANDOM**：应在 prefill/decode 阶段动态切换（prefill 用 SEQUENTIAL 保预读、decode 用 RANDOM 按需），或仅对 MoE 专家区域设置——当前静态全量实现是负优化主因。
- **KV eviction**：值得保留与深化，是端侧内存受限场景的实际价值点。
- **预取**：在快 SSD 场景可考虑默认关闭或加大窗口阈值。

### 6.3 限制

- 无 root：无法 cgroup 限内存制造更极限的内存压力、无法 drop_caches（冷热缓存为近似）。
- llama-bench 不支持 `-c`，bench 组上下文由 `-p 512` 推导，KV cache 压力主要靠 cli 的 `-c` 体现。
- 80B decode 慢，长生成 -n 256 已属极限（单组 20-40 分钟），更长生成未覆盖。
