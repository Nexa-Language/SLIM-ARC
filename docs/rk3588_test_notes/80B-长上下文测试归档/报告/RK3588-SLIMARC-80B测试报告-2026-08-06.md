## 3. 冒烟测试结果（Phase 2）

命令：`llama-cli -m <80B> -p "Hello, how are you?" -n 16 -c 256 -t 4 -st -no-cnv`

| 配置 | Prompt (t/s) | Generation (t/s) | 耗时 | RSS 峰值 | EXIT |
|:---|:---:|:---:|:---:|:---:|:---:|
| 默认（SLIM-ARC 全开） | 0.5 | 0.5 | 122.0s | 6.29 GiB | 0 |
| `SLIM_ARC_DISABLE=1` | 1.7 | 1.9 | 54.8s | 6.26 GiB | 0 |
| `SLIM_ARC_NO_MADV_RANDOM=1` | 1.4 | 1.8 | 55.4s | 6.50 GiB | 0 |

**结论**：80B 模型在 8GB 内存 RK3588 端侧三种配置下均成功完成推理（EXIT=0，无 OOM）。默认配置输出示例："Hello! I'm doing great, thank you for asking! 😊 How about"

**关键证据（mmap 按需分页）**：进程虚拟地址空间 46.6 GiB（映射完整 45GiB 模型），但 RSS 峰值仅 6.29 GiB —— 权重并未全部载入物理内存，按需分页生效。

## 5. SLIM-ARC 专项验证（Phase 4）

### 5.1 验证方法

系统无 strace 且无 root 安装，采用 **LD_PRELOAD 拦截库**（`madvise-trace.so`）拦截 `posix_madvise`/`madvise` 系统调用，直接观测 SLIM-ARC 的 madvise 行为。

### 5.2 madvise 调用观测

**默认配置（SLIM-ARC 全开）：**

| advice | 长度 | 调用次数 | 来源 |
|:---|:---|:---:|:---|
| **RANDOM** | 48,410,988,384 B（45.1 GiB） | 1 | **SLIM-ARC MADV_RANDOM 按需分页**（`msz > 6GiB` 触发）✅ |
| **WILLNEED** | 48,410,988,384 B（45.1 GiB） | 1 | mmap 初始预取 / SLIM-ARC 预取 ✅ |
| DONTNEED | 6,291,456 B（6 MiB） | 3 | KV cache 页释放 |

**`SLIM_ARC_NO_MADV_RANDOM=1` 配置：**

| advice | 调用次数 |
|:---|:---:|
| RANDOM | **0（消失）** |
| WILLNEED | 1（保留） |
| DONTNEED | 3 |

### 5.3 结论

1. **SLIM-ARC MADV_RANDOM 按需分页在端侧 >6GB 模型上首次确认触发**（45.1GiB 完整映射设置 RANDOM 提示）。
2. 开关有效性验证：`SLIM_ARC_NO_MADV_RANDOM=1` 后 RANDOM 调用消失、WILLNEED 保留，与代码设计完全一致。
3. **填补昨日报告 §7 的空白**：昨日 4B/OLMoE（<6GB）无法触发 MADV_RANDOM，今日 80B 首次在真实端侧验证核心机制。

## 7. 结论与限制

### 7.1 达成情况（对照计划 §1 目标）

| 目标 | 结果 |
|:---|:---|
| G1：80B 在 8GB RK3588 上 mmap 加载并推理 | ✅ 完成（EXIT=0，正常输出） |
| G2：MADV_RANDOM 按需分页在 >6GB 模型触发 | ✅ 确认触发（45.1GiB RANDOM 调用） |
| G3：预取调度器启用 | ✅ 确认（WILLNEED 调用 + B4 消融） |
| G4：端侧性能（pp/tg/TTFT/RSS） | ✅ 完整采集 |
| G5：SSD 带宽影响 | ✅ 实测 2.1GB/s，容量+带宽瓶颈解除 |

### 7.2 关键发现

1. **存储条件根本改善**：SSD 读 2.1GB/s（microSD 的 30 倍），45GiB 模型可完整存放与 mmap 映射。
2. **SLIM-ARC 首次端侧触发验证**：MADV_RANDOM 在 80B 上生效，且可用开关精确控制。
3. **SLIM-ARC 当前存在性能代价**：MADV_RANDOM 关闭 readahead 使 prefill 变慢（pp 0.39 vs 2.02）。这是设计权衡——换取 decode 时按需分页避免争用。在端侧 8GB 内存 + 45GiB 模型的极端场景下，内存受限严重，按需分页是可行的关键，但其性能收益需在更长生成、更大 KV cache 场景下进一步评估。

### 7.3 限制

- 无 root：无法 cgroup 限内存、无法 drop_caches、无法安装 strace（已用 LD_PRELOAD 替代）。
- KV eviction（`SLIM_ARC_KV_EVICT=1`）未在本次深度验证（内存未紧张到需要逐 token 驱逐）。
- 80B decode 极慢（0.23 t/s），本次生成长度受限（16-32 tokens），长文本生成未覆盖。
