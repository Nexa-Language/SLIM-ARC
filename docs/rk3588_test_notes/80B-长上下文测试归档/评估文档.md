# 评估文档：RK3588 80B 长上下文测试

- 评估日期：2026-08-07
- 评估对象：RK3588 端侧 80B 实验 + 长上下文测试
- 评估维度：成功性判断、项目意义、与 x86 WSL 对比、后续建议

---

## 1. 本次测试是否成功？——辩证评估

### 1.1 技术验证层面：✅ 完全成功

| 验证项 | 结果 |
|:---|:---|
| 45GB 模型在 8GB 物理内存端侧部署 | ✅ 成功（mmap 按需分页，RSS ~6.5GB，无 OOM） |
| SLIM-ARC 机制触发 | ✅ MADV_RANDOM（45.1GiB）/ 预取 WILLNEED / KV eviction 全部确认 |
| KV eviction 端侧有效性 | ✅ 窄窗口降 RSS（6.34 < 6.49 GiB），输出连贯 |
| 数据完整性 | ✅ 26 组测试全部 EXIT=0，完整留痕 |
| 真实端侧验证空白 | ✅ 首次在真实硬件（非 WSL cgroup 模拟）验证 |

### 1.2 性能目标层面：❌ 未达成

- SLIM-ARC 全开比禁用慢 3-4×（0.53 vs 2.13 t/s），长上下文未改善
- 预取无 decode 交叉点；MADV_RANDOM 为主要性能杀手

### 1.3 综合判断

> **技术验证成功 + 性能目标失败 + 认知突破**。测试结果不是"成功"或"失败"的二元结论，而是揭示了 SLIM-ARC 在真实端侧（ARM 弱算力 + 物理内存 + 快 SSD）环境下的机制适配问题。

---

## 2. 没有本项目，端侧能否部署该模型？——关键结论

### 答案：**能，且更快**

| 场景 | 能否运行 | decode 速度 |
|:---|:---:|:---:|
| 无 SLIM-ARC（纯上游 llama.cpp） | ✅ | 0.89-2.15 t/s |
| 有 SLIM-ARC 全开 | ✅ | 0.23-0.57 t/s |

**原因（源码证实）**：
1. **llama.cpp 上游自带 mmap 按需分页**（默认 `LLAMA_LOAD_MODE_MMAP`）——"45GB 在 8GB 上能跑"是操作系统 + 上游已实现的能力。
2. **RK3588 物理 8GB + 快 SSD（2.1GB/s）** 使上游默认 `FADV_SEQUENTIAL + MAP_POPULATE` 顺序预读天然高效。
3. SLIM-ARC 的 MADV_RANDOM 反而关闭了这个高效预读，且 ARM 算力不足使按需分页收益被掩盖。

---

## 3. 与 x86 WSL 预期结果的对比

### 3.1 数据对比

| 指标 | x86 WSL (8GB) | RK3588 (8GB) |
|:---|:---:|:---:|
| baseline/禁用 tg | 0.08 | 0.89-2.15 |
| SLIM-ARC 全开 tg | 0.43 | 0.23-0.57 |
| SLIM-ARC 相对收益 | **+437%** | **-70%~-80%** |
| MADV_RANDOM 贡献 | +262% | 负贡献 |
| 量化 | IQ4_XS + KV q4_0 | 仅 Q4_K_M |

### 3.2 差异根本原因

**原因 1（最关键）：baseline 环境不同**
- x86 WSL：cgroup **硬限制** 8GB + 虚拟化，上游 mmap 全量映射导致频繁缺页/swap，baseline 极慢（0.08）→ SLIM-ARC 按需分页救场（+437%）
- RK3588：**物理** 8GB + 快 SSD，上游顺序预读天然高效，禁用反而快 → SLIM-ARC 干扰（-70%）

**原因 2：ARM 算力瓶颈**
- x86 有 AVX2/VNNI，算力强 → I/O 是瓶颈 → MADV_RANDOM 的 I/O 优化兑现为加速
- RK3588 无 AVX2，计算是瓶颈 → I/O 优化被计算瓶颈掩盖，只剩 prefill 惩罚

**原因 3：量化策略**
- x86 最优解叠加 IQ4_XS（40GB）+ KV q4_0；RK3588 仅 Q4_K_M（45GB），工作集更大

---

## 4. 项目意义与定位建议

### 4.1 核心意义

1. **填补真实端侧验证空白**——26 组真实硬件数据比 WSL 模拟更可信
2. **暴露前提缺陷**：SLIM-ARC 收益依赖"算力>I/O + 内存硬限制"，真实端侧（ARM 弱算力、物理内存+快SSD）不满足
3. **KV eviction 是唯一可迁移到端侧的资产**——被证明真实有效

### 4.2 对项目的建议

| 机制 | 建议 |
|:---|:---|
| MADV_RANDOM | 在 ARM 端侧应谨慎或仅用于 MoE 专家区域；实现 prefill(SEQUENTIAL)/decode(RANDOM) 动态切换 |
| 预取 | 快 SSD 场景建议默认关闭或加大窗口阈值 |
| KV eviction | **保留并深化**——端侧内存受限场景的实际价值点 |
| 方向 | 从"纯 I/O 优化"转向"针对端侧算力/内存特征的综合优化" |

---

## 5. 一句话总结

> RK3588 长上下文测试证明：80B 模型可部署在 8GB 物理内存端侧（无本项目也能跑且更快），SLIM-ARC 在真实端侧整体负优化，KV eviction 是唯一正收益机制。与 x86 WSL 的 +437% 正收益相反，根因是 baseline 环境差异（物理内存+快SSD vs cgroup 硬限制）与 ARM 算力瓶颈。项目的价值主张需要从"纯 I/O 优化"转向"针对端侧算力/内存特征的综合优化"。
