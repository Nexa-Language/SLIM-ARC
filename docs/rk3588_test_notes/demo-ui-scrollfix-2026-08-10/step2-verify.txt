【原理说明】为何该改动让用户可在生成期间回看:
- 流式输出时每个 token 回调都执行旧逻辑 `messages.scrollTop = messages.scrollHeight;`
  → 无条件把滚动位置钉死在底部，用户一旦向上翻看，下一个 token 到达即被拉回底部。
- 新逻辑先判断 `messages.scrollTop + messages.clientHeight >= messages.scrollHeight - 50`
  （即当前可视区底部距内容底部在 50px 内，等价于"用户仍在底部附近"），仅在此时才滚动到底。
- 用户向上翻看时该条件为假，不再强制滚动，可自由回看历史；回到底部附近后又自动跟随输出。
- 行 460（发送新消息时）保留无条件滚动：发送时定位到底部是合理 UX，符合分析报告建议。

   c) 翻回底部附近后: 自动滚动跟随恢复。
4. 发送新消息瞬间: 页面仍会立即滚到底部（行 460 逻辑保留），属预期行为。
