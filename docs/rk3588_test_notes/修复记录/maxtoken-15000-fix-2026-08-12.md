# UI max_tokens 上限提升至 15000 修复记录

- **日期**: 2026-08-12
- **文件**: [`scripts/demo/index.html`](../../scripts/demo/index.html)、[`scripts/demo/start-demo.sh`](../../scripts/demo/start-demo.sh)、[`scripts/demo/monitor.py`](../../scripts/demo/monitor.py)
- **修复类型**: SLIM-ARC FIX 2026-08-12（最小外科手术式改动）

## 改动内容

### 1. 前端 max_tokens 上限提升

[`index.html`](../../scripts/demo/index.html) 中聊天请求的 `max_tokens` 从 **512** 提升到 **15000**：

```javascript
// SLIM-ARC FIX 2026-08-12: 对比实验需要长输出，上限从 512 提升到 15000
max_tokens: 15000,
```

### 2. 80B 取消 -c 限制（配合长输出）

用户确认可接受"启动更慢"的代价，将 80B 的 context 从 `1024` 改为 `0`（llama.cpp 中 `-c 0` = 加载模型训练上下文，即不限制）：

- [`start-demo.sh`](../../scripts/demo/start-demo.sh:51)：80b 分支 `MODEL_CTX=0`
- [`monitor.py`](../../scripts/demo/monitor.py:105)：80b 配置 `"ctx": 0`（UI 热切换链路同步）

4B 保持 `2048` 不变。

## 说明

- UI 聊天走 **llama-server 主链路**（`http://HOST:8080/v1/chat/completions`），`max_tokens` 由前端显式传参。
- llama-server 不会因 `max_tokens`（n_predict）超过 `n_ctx` 而拒绝请求（只检查 prompt 输入 token 数，见 llama.cpp `server-context.cpp`）；生成到 context 满即停（`--no-context-shift`）。
- `-c 0` 使 KV cache 按模型训练上下文预分配，启动更慢、KV 预分配更大，但能承载 15000 token 长输出。
- [`llama_cli_server.py`](../../scripts/demo/llama_cli_server.py) 为 fallback 备用链路（当前未使用），默认 `max_tokens=200` 会被前端显式传参覆盖，无需改动。

- HTML/JS 大括号配对校验通过（script 块 `{`/`}` 均 100 个）✓

## 风险提示

- 80B 取消 `-c` 限制后 KV cache 按训练上下文预分配，内存占用增大；8GB 设备上启动更慢，极端情况下有 OOM/swap 风险（Qwen3-Next-80B 为混合 SSM 架构，KV 增长有限，见长上下文测试文档估算）。
- 如需回退，将 80b 的 `MODEL_CTX` / `"ctx"` 改回 `1024` 即可。
