# KV 量化参数化切换（q4_0 / f16）改动留痕

- 日期：2026-08-12
- 类型：实验参数化（非 bug、非核心机制改动）
- 红线规则遵守：仅参数化启动参数取值方式，未修改任何 llama.cpp 源码 / patch / 核心机制，未新增功能、未改算法逻辑。所有改动均标注 `SLIM-ARC FIX 2026-08-12` 注释。
- 相关任务：SLIM-ARC demo UI 的 llama-server 启动链路 KV cache 量化格式参数化覆盖，使实验可在「KV q4_0（默认）」与「KV F16」之间切换。

---

## 一、改动文件与具体改动点

### 1. `scripts/demo/start-demo.sh`（一键启动链路）

- **第 112 行**（原第 109 行）：
  - 原：`export SLIM_ARC_KV_TYPE=q4_0`（硬编码，用户无法覆盖）
  - 新：`export SLIM_ARC_KV_TYPE="${SLIM_ARC_KV_TYPE:-q4_0}"`
  - 效果：默认仍是 `q4_0`；若外部已设 `SLIM_ARC_KV_TYPE=f16`，则导出为 `f16`，并透传给 monitor.py。
- **第 129 行**（原第 124 行）：
  - 原：`-fa auto -ctk q4_0 -ctv q4_0 --no-repack --no-context-shift`
  - 新：`-fa auto -ctk "${SLIM_ARC_KV_TYPE:-q4_0}" -ctv "${SLIM_ARC_KV_TYPE:-q4_0}" --no-repack --no-context-shift`
  - 效果：`-ctk` / `-ctv` 取值跟随 `SLIM_ARC_KV_TYPE`，默认 `q4_0`，`f16` 时用 `f16`；其余参数（`-fa auto`、`--no-repack`、`--no-context-shift` 等）不变。

### 2. `scripts/demo/monitor.py`（UI 热切换链路）

- **MODEL_CONFIGS `4b` 与 `80b`**（约第 91-93、110-112 行）：各自新增
  ```python
  # SLIM-ARC FIX 2026-08-12: KV 量化参数化（SLIM_ARC_KV_TYPE，实验用），
  # 与 start-demo.sh 保持一致：默认 q4_0，SLIM_ARC_KV_TYPE=f16 时用 f16。
  "kv_type": CONFIG["kv_type"],
  ```
  `CONFIG["kv_type"]` 已在文件头部从环境变量读取（`os.environ.get("SLIM_ARC_KV_TYPE", "q4_0")`，第 50 行），默认 `q4_0`。
- **`_build_llama_cmd()`**（约第 376-392 行）：`"-ctk", "q4_0", "-ctv", "q4_0"` 改为由 `cfg["kv_type"]` 取值：
  ```python
  kv_type = cfg["kv_type"]
  ...
  "-ctk", str(kv_type),
  "-ctv", str(kv_type),
  ```
  效果：UI 热切换链路（4b/80b 切换后重新拉起 llama-server）生成的 `-ctk` / `-ctv` 与一键启动链路保持一致，同样受 `SLIM_ARC_KV_TYPE` 控制。

> 说明：`scripts/demo/llama_cli_server.py` 与 `scripts/demo/README.md` 中亦有同类硬编码/文档示例，但本任务范围仅限定 `start-demo.sh` 与 `monitor.py` 两个 demo 启动脚本，故未越界修改。

## 二、环境变量用法

| 环境变量 | 取值 | 默认 | 作用 |
|---------|------|------|------|
| `SLIM_ARC_KV_TYPE` | `q4_0` / `f16` | `q4_0` | 控制 llama-server 的 `-ctk` / `-ctv` KV cache 量化格式 |

### 启动命令示例

**一键启动（KV F16 对照实验组）：**
```bash
SLIM_ARC_KV_TYPE=f16 SLIM_ARC_DISABLE=1 bash scripts/demo/start-demo.sh 80b
```

**一键启动（默认 KV q4_0 对照组，无需设变量）：**
```bash
bash scripts/demo/start-demo.sh 80b
```

**UI 热切换链路：** 以 `SLIM_ARC_KV_TYPE=f16`（或 `q4_0`）启动 start-demo.sh 后，`SLIM_ARC_KV_TYPE` 会通过 export 透传给 monitor.py；后续在 UI 上 4b/80b 热切换时，`_build_llama_cmd()` 也会沿用该值生成 `-ctk`/`-ctv`，与一键启动链路一致。

## 三、默认行为不变说明

- 未设置 `SLIM_ARC_KV_TYPE` 时，两处链路均按原硬编码行为生成 `-ctk q4_0 -ctv q4_0`，与改动前完全一致。
- 未改动任何 llama.cpp 源码、patch、核心机制、算法逻辑；仅将 demo 脚本中 `-ctk`/`-ctv` 的取值方式从硬编码改为读取环境变量。
- 已存在的 `SLIM_ARC_CTX`（覆盖 `-c`）先例与本改动保持同样风格，均属「环境变量覆盖启动参数」的参数化，不改变默认行为。
