# 80B llama-server 启动 OOM 修复记录（-c 0 → 16384）

- **日期**: 2026-08-12
- **设备**: RK3588（7.8 GiB 物理内存，zram swap 未启用，`SwapTotal=0`）
- **修复类型**: SLIM-ARC FIX 2026-08-12（默认 context 调整，最小外科手术式改动，未改核心机制）

## 现象

```bash
bash scripts/demo/start-demo.sh 80b
```

llama-server 启动过程中进程被内核 OOM Killed，无法提供 HTTP 服务：

```
[1/3] 启动 llama-server...
  PID: ...
  ⚠️ llama-server 进程已退出！查看 logs/demo-llama-server.log
Killed
```

- 匿名内存（Anonymous）升至约 5.8GB，超过 7.8GiB 物理可用，触发 OOM。
- `dmesg` 可见 `Out of memory: Killed process ... (llama-server)`。

## 根因分析 (Root Cause)

- 此前为支持 15000 token 长输出，把 80B 的 context 从 `-c 1024` 改为 `-c 0`。
- llama.cpp 中 `-c 0` = 按模型**训练上下文** `n_ctx_train` 预分配 KV cache。
  Qwen3-Next-80B-A3B-Instruct 的 `n_ctx_train = 262144`（256K）。
- 256K context 预分配的 KV cache 约 **1.5GB**，叠加模型按需加载/权重映射等，
  匿名内存升至 **5.8GB**，超过物理可用（7.8GiB 且 swap 未启用，`SwapTotal=0`）
  → 内核 OOM Killed。
- Debug 对照实测：
  - `-c 1024`：正常启动（VmRSS 4.0GB，HTTP 200）。
  - `-c 0`：KV 预分配 1.5GB，匿名内存 5.8GB → OOM Killed。

## 修复方案

将 80B 默认 context 从 `0` 改为 **16384**：

| 文件 | 行 | 改动 |
| --- | --- | --- |
| [`scripts/demo/start-demo.sh`](../../scripts/demo/start-demo.sh) | ~51 → ~55 | 80b 分支 `MODEL_CTX=0` → `MODEL_CTX=16384`，并更新注释说明 |
| [`scripts/demo/monitor.py`](../../scripts/demo/monitor.py) | ~108 → ~111 | 80b 配置 `"ctx": 0` → `"ctx": 16384`（UI 热切换链路同步），并更新注释说明 |

改动内容（均标注 `// SLIM-ARC FIX 2026-08-12: ...`）：

1. `MODEL_CTX`（一键启动 80b 分支）与 `ctx`（UI 热切换 80b 配置）同步改为 `16384`。
2. 注释补充说明：
   - **16384 为 8GB 设备安全值**：KV cache 仅 **96MiB**，实测安全；
   - 可覆盖 **15000 token 长输出 + ~1K prompt**；
   - `-c 0` 会按 256K 训练上下文预分配 **1.5GB KV** 导致 OOM（2026-08-12 实测）。

## 修复验证

```bash
bash -n scripts/demo/start-demo.sh        # 通过
python3 -m py_compile scripts/demo/monitor.py  # 通过
grep -n "16384" scripts/demo/start-demo.sh scripts/demo/monitor.py
# start-demo.sh:  MODEL_CTX=16384
# monitor.py:     "ctx": 16384,（80b 配置；4b 仍为 2048）
```

- 两处均为 16384，4b 配置不受影响（仍为 2048）。
- 静态校验通过（bash -n / py_compile）。

## 附加说明

- 用户也可用环境变量临时覆盖（不修改文件）：
  ```bash
  SLIM_ARC_CTX=16384 bash scripts/demo/start-demo.sh 80b
  ```
  本次已直接修改默认值，无需再依赖环境变量。
- 若确需更大上下文（如 **32768**），KV cache 192MiB 仍安全（8GB 设备可承载），
  可另行调整，但**默认推荐 16384**。

## 建议：正确启用 swap（供参考，非本次改动）

设备当前 `SwapTotal=0`（zram swap 未启用）。如需为更大上下文/更大模型提供
内存兜底，可正确启用 zram swap：

```bash
# 方式一：手动启用 /dev/zram0（需内核已加载 zram 且 /dev/zram0 存在）
sudo mkswap /dev/zram0 && sudo swapon /dev/zram0

# 方式二：按 /etc/fstab 或 systemd 配置启用全部 swap 设备
sudo swapon -a
```

> 注意：swap 只能作为兜底，swap 风暴下推理吞吐会显著下降；对 80B 建议仍以
> 合理 context（16384）控制 KV 预分配为主。
