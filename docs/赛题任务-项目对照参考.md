## 1. 赛题信息（官方）

| 项 | 内容 |
|---|---|
| 命名日期 | 2026-04-12 |
| 大赛 | 2026年全国大学生计算机系统能力大赛-操作系统设计赛(全国)-OS功能挑战赛道 |
| 赛题 | 内存受限环境的大语言模型推理优化问题 / Runtime Optimization of LLM Inference for the Memory Constraint System |
| 难度/类型 | A / 学术型 |
| 赛题维护 | 南开大学，宫晓利（gongxiaoli@nankai.edu.cn） |

**赛题背景**：模型海量参数与运行时 KV cache 造成巨大内存需求，资源受限场景难以部署；但 LLM 推理访存行为固定、专家激活数量少，为虚拟内存、数据预取等技术提供施展空间，使压缩运行时内存成为可能。

**赛题任务（三条）**：
1. 分析 LLM 推理过程的访存行为，包括但不限于参数加载、KV cache 使用、专家激活等。
2. 使用虚拟内存相关技术，通过按需加载、数据换出等策略减少运行时所需的物理内存量。
3. 通过预取等技术掩盖 IO 延迟，提升推理性能。

**赛题特征**：注重嵌入式/边缘设备上的大模型部署；强调全局系统观念——数据访问、传输、硬件特性、计算精度等多因素耦合场景的处理。

**参考资料**：FlexInfer: Breaking Memory Constraint via Flexible and Efficient Offloading for On-Device LLM Inference (EuroMLSys 2025)。

**评审要点**：注重系统完成度与可演示性，**避免针对单一指标而无视其他因素的方案**。

## 3. 三线实测数据概览（截至 2026-08-13）

| 维度 | WSL x86 (8G cgroup) | RK3588 (8G 物理) | Pi5 (4G 物理) |
|---|---|---|---|
| baseline tg | 0.08 t/s | 0.89–2.15 t/s | 4.6 t/s (Qwen3-4B) |
| SLIM-ARC 全开 tg | 0.43 t/s (**+437%**) | 0.23–0.57 t/s (-70%~-80%) | 80B 0.1 t/s，**比禁用快 13.4%** |
| 关键机制 | MADV_RANDOM +262% | MADV_RANDOM 负贡献（FADV_SEQUENTIAL 更优） | expert prefetch 主导正收益 |
| 80B 可运行性 | ✅ | ✅（RSS ~6.5GB） | ✅（RSS ~2.8GiB，zram swap 仅 ~50MB） |

> **关键认知**（来自 RK3588 评估文档与本次 Pi5 探测）：SLIM-ARC 各机制收益强依赖硬件/存储特性。
> 同一套代码在三条线上结论相反（x86 正、RK3588 负、Pi5 默认路径反超禁用），正好体现赛题
> "多重因素相互影响的复杂场景" 的考察点——**这本身是评审论据，不是项目缺陷**，但要求
> 我们提供自适应开关（opt-in env）而非单一固定配置。

## 4. Pi5 4GB 80B 探测原始结论（2026-08-13，详见 `docs/pi5_4GB_test_notes/2026-08-13-rerun/80b-probe/`）

| 配置 | 耗时(s) | PEAK_RSS | prefetch issued/hit/waste/hit_rate |
|---|---:|---:|---|
| 默认（SLIM-ARC 全开） | 461 / 457（复现） | 2.78–2.92 GiB | 8718.8MB / 2735.5MB / 5983.2MB / 31.38% |
| `SLIM_ARC_DISABLE=1` | 532 | 2.85 GiB | — |
| `SLIM_ARC_NO_MADV_RANDOM=1` | 543 | 2.99 GiB | issued 8718.8MB（同默认） |
| `SLIM_ARC_EXPERT_CONF=1` | 457 | 2.91 GiB | 3179.2MB / 1401.6MB / 1777.6MB / **44.09%** |
| `SLIM_ARC_EXPERT_BUDGET=1` | 457 | 2.89 GiB | 5218.9MB / 1568.8MB / 3650.1MB / 30.06% |
| CONF+BUDGET | 461 | 2.92 GiB | 2360.2MB / 1160.4MB / **1199.7MB** / **49.17%** |
| CONF+BUDGET+KV_EVICT | 453 | 2.91 GiB | 同上 + `KV eviction: ENABLED` |
| decode32 默认 | 455 | — | issued 8718.8MB / hit 3747.9MB / hit_rate 42.99% |

**结论**：
1. 45GB MoE 在 4GB RAM 上可运行且稳定（三组复现 ±4s），满足赛题"压缩运行时内存"核心要求。
2. CONF+BUDGET 组合为当前 Pi5 最佳：预取 I/O 量降 73%，waste 降 80%，hit_rate 49.2%，耗时最短（453–461s）。
3. 吞吐瓶颈为 0.1 t/s（每 token ~5s），主要来自 FUSE(NTFS-3G) 缺页 + 4 核 A76 算力，后续改进方向见 §5。

## 5. 改进方向清单（按评审要点排序）

> 评审要点提醒：**完成度与可演示性优先，避免单一指标优化**。以下方向按"可演示性 × 投入产出"排序。

1. **自适应机制开关（P0，呼应评审"全局系统观念"）**：把当前 env 开关演进为运行时自动探测
   （存储类型 FUSE/ext4、内存压力、模型规模 → 自动选择 madvise 策略与预取门控），
   用单一入口消除三线结论相反的尴尬。不修改核心机制代码，只加探测与策略选择层。
2. **expert 浪费回收（P1）**：按 `plan/24-v1-expert-waste-reclamation.md` 推进，
   Pi5 实测 waste=5983MB 提供了真实回收收益空间（CONF+BUDGET 后仍有 1200MB）。
3. **FUSE 存储适配（P1，Pi5 专属）**：NTFS-3G 下 madvise(WILLNEED) 走 FUSE readahead，
   需验证 `posix_fadvise(POSIX_FADV_WILLNEED)` 与 mmap+madvise 的等效性；
   备选：将 80B 迁移至 ext4 分区做 A/B，量化 FUSE 损耗（若瓶颈文档确认则归档为环境限制）。
4. **KV eviction 长上下文实证（P2）**：RK3588 已证窄窗口降 RSS（6.34<6.49 GiB），
   Pi5 4GB 更需要该证据；设计 -c 2048+ 的多轮对话压测触发真实 evict。
5. **可演示性（P2）**：demo-ui（RK3588 已有）移植到 Pi5，展示 metrics 实时输出
   （expert prefetch 统计已是现成素材）。
6. **decode 速度深挖（P3，谨慎）**：0.1 t/s 的 80B decode 受算力限制，属"单一指标"，
   仅在完成 1-4 后作为补充，不作为主线宣传。

## 6. 风险与红线（改进时必须遵守）

1. 不修改 `patches/llama-upstream/` 核心机制代码；扩展走新文件或 env 门控 opt-in。
2. 三线数据严格隔离（pi5_4GB_test_notes / rk3588_test_notes / yituodabian_test_notes）。
3. 所有数据必须真实可复现（命令、EXIT、时间戳留痕），负面结果如实记录（评审要点明确反对指标粉饰）。
4. 无 sudo 环境限制（Pi5）：无法 drop_caches / 无法启 memory cgroup，冷启动与内存控制类实验必须注明该局限。
